#### 7. 약속 정하기 (appointment)

##### 목표

약속을 잡는 세 사람이 차례로 보여 주는 선호(요일·위치·메뉴·탄 버스)를 기억했다가 질문에 맞는 답을 고른다. 짧게 제시되는 정보를 기억하고 활용하는 작업기억을 평가한다.

##### 진행 방식

1. 세 사람이 한 명씩 자신의 선호 목록을 잠깐 보여 주고 사라진다. 세 사람의 목록을 동시에 볼 수는 없다.
2. 세 번째 사람까지 보여 준 뒤 질문과 선택지가 나온다. 플레이어는 답 하나를 클릭한다.
3. 라운드는 4개다.
   1. 1라운드(요일): 각자 요일 3개를 보여 준다(라운드 후반 문제는 4개). 셋 모두 고른 요일 하나를 고른다. 선택지는 월~일 7개.
   2. 2라운드(위치): 4×4 지도에서 각자 칸 4개를 표시한다(후반 5개). 셋 모두 표시한 칸 하나를 고른다. 선택지는 16칸.
   3. 3라운드(메뉴): 각자 메뉴 3개를 보여 준다(후반 4개). 셋 모두 고른 메뉴 하나를 고른다. 선택지는 메뉴 8개.
   4. 4라운드(버스): 각자 자신이 탄 버스 번호 2개를 보여 준다(후반 3개). **아무도 타지 않은** 번호 하나를 고른다. 선택지는 세 사람이 탄 번호 전부와 아무도 타지 않은 번호 하나.
4. 1~3라운드의 정답은 항상 정확히 하나만 겹치도록 만든다. 4라운드의 정답도 하나뿐이다.

##### 제한 사항

- 사람마다 제시 시간이 있다(기본 3초). 사람 사이에는 0.5초 빈 화면이 있다.
- 질문이 나온 뒤 응답 제한 시간이 있다(기본 7초). 시간이 지나면 오답 처리하고 다음 문제로 넘어간다.

##### 데이터의 저장 및 분석

문제마다 라운드, 사람별 제시 항목, 정답, 플레이어의 답, 정답 여부, 응답 시간, 제시 항목 수(3개/4개 등)를 저장한다. 라운드별·제시 항목 수별 정답률로 어떤 유형(특히 규칙이 뒤집히는 4라운드)에 약한지 본다.

##### 연습게임 개발 방향

- 라운드를 하나만 고르거나 전체 라운드를 순서대로 플레이할 수 있다.
- 라운드당 문제 수(2~10, 기본 4), 사람별 제시 시간(1~5초, 기본 3초), 응답 제한 시간(3~15초, 기본 7초)을 바꿀 수 있다.
- 공개 자료(잡다 전략게임 안내·연습 사이트 공략)에서 확인되지 않은 수치(항목 수·제시 시간·선택지 수)는 위 기본값으로 정했다.


#### 8. 길 만들기 (path)

##### 목표

모든 교통수단이 같은 색 손님에게 도착하도록 게임판에 울타리를 설치한다. 최소한의 울타리 개수와 클릭 횟수로 효율적으로 계획하는 능력을 평가한다.

##### 진행 방식

1. 격자 게임판 바깥 가장자리에 교통수단과 손님이 있다. 교통수단은 판 안쪽을 향해 출발한다.
2. 칸을 클릭하면 울타리가 바뀐다: 빈칸 → `/` → `\` → 빈칸.
3. 교통수단은 직진하다가 울타리를 만나면 진행 방향이 90° 꺾인다.
   - `/`: 오른쪽으로 가던 차는 위로, 위로 가던 차는 오른쪽으로, 왼쪽으로 가던 차는 아래로, 아래로 가던 차는 왼쪽으로.
   - `\`: 오른쪽 → 아래, 아래 → 오른쪽, 왼쪽 → 위, 위 → 왼쪽.
4. 각 교통수단의 경로는 겹쳐도 된다.
5. 화면에 '정답 울타리 수'(필요한 최소 개수)를 보여 준다.
6. '출발'을 누르면 모든 교통수단이 움직이고, 모두 같은 색 손님에게 도착하면 성공이다. 실패하면 경로를 보여 주고, 다시 고쳐서 출발할 수 있다.
7. 라운드가 오를수록 판이 커지고 교통수단이 늘어난다: 1라운드 4×4·2대, 2라운드 5×5·3대, 3라운드 6×6·3~4대.

##### 제한 사항

- 라운드마다 전체 제한 시간이 있다(기본 3분). 시간 안에 최대한 많은 문제를 푼다. 시간이 끝나면 풀던 문제는 미해결로 기록한다.
- '건너뛰기'로 문제를 포기하고 다음 문제로 갈 수 있다(미해결 기록).

##### 데이터의 저장 및 분석

문제마다 성공 여부, 사용한 울타리 수와 최소 울타리 수, 클릭 수와 최소 클릭 수, 출발 시도 횟수, 소요 시간을 저장한다. 성공 문제 중 최소 울타리로 푼 비율과 클릭 초과량으로, 머릿속으로 계획하고 클릭하는지 시행착오로 푸는지를 피드백한다.

##### 연습게임 개발 방향

- 문제는 무작위로 만들고, 탐색기로 최소 울타리 수와 그때의 최소 클릭 수를 계산해 정답 기준으로 쓴다.
- 최소 클릭 수: 울타리 하나가 `/` 면 1번, `\` 면 2번 클릭해야 놓인다.
- 시간이 끝났을 때 한 번도 누르지 않은 문제는 기록하지 않는다.
- 연습 모드에서는 '정답 보기'로 최소 울타리 배치를 볼 수 있다(그 문제는 미해결로 기록).
- 공개 자료에 판 크기·교통수단 수·제한 시간이 없어서 위 값으로 정했다.


#### 9. 마법약 만들기 (potion)

##### 목표

재료 카드 조합에 따라 빨간 약 또는 파란 약이 만들어진다. 결과를 보며 조합의 규칙을 학습하고, 도중에 바뀌는 규칙에도 적응해 어떤 약이 나올 가능성이 높은지 예측한다. 학습능력을 평가한다.

##### 진행 방식

1. 재료 카드 4장이 2×2로 놓여 있다. 매 문제 1~3장이 앞면으로 공개된다(조합 14가지: 1장 4개, 2장 6개, 3장 4개).
2. 조합마다 잘 나오는 색이 정해져 있다(레시피). 재료 하나하나가 아니라 조합 전체가 색을 정한다.
3. 플레이어는 ← (파란 약) 또는 → (빨간 약)으로 이번에 나올 가능성이 높은 약을 고른다.
4. 고른 직후 실제로 만들어진 약을 보여 준다. 결과는 확률이라, 같은 조합에서도 가끔 반대 색이 나온다(기본 80:20).
5. 게임 중간에 예고 없이 레시피 일부(14가지 중 4가지)가 뒤집힌다.

##### 제한 사항

- 문제마다 응답 제한 시간이 있다(기본 3초). 시간이 지나면 오답 처리하고 실제 결과만 보여 준다.

##### 데이터의 저장 및 분석

- 정답 기준은 실제로 나온 색이 아니라 **현재 레시피에서 나올 가능성이 높은 색**이다.
- 채점에서 빼는 문제: 그 조합을 처음 본 문제, 레시피가 바뀐 조합을 바뀐 뒤 처음 본 문제. 이 문제들은 알 방법이 없기 때문이다.
- 문제마다 조합, 레시피상 색, 실제 결과, 플레이어의 답, 채점 여부, 레시피 변경 전/후, 바뀐 조합 여부를 저장한다.
- 변경 전 정답률, 변경 후 바뀐 조합 정답률(적응), 변경 후 바뀌지 않은 조합 정답률(괜히 바꿔 답하지 않았는지)을 따로 본다.

##### 연습게임 개발 방향

- 문제 수(20~120, 기본 60), 응답 제한 시간(2~5초, 기본 3초), 우세 색 확률(60~95%, 기본 80%), 레시피 변경 여부(기본 켬)를 바꿀 수 있다.
- 결과를 보고 규칙을 익히는 게임이라 연습·실전 모드를 나누지 않는다. 게임 중에는 실제로 만들어진 약만 보여 주고, 채점 여부·레시피 변경은 결과 화면에서만 알려 준다(게임 중에 알려 주면 레시피 변경에 적응하는 연습이 되지 않는다).
- 레시피 변경 시점은 전체의 40~60% 사이에서 무작위로 정한다.
- 공개 자료에서 확인되지 않은 수치(문제 수·확률·변경 시점·바뀌는 조합 수)는 위 기본값으로 정했다.
